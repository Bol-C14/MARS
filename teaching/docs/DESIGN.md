# MIPS 教学 IDE：设计原则与实施 Goal

版本：0.2 · 2026-10-21 · 状态：M0–M2 已实现并通过本地验收；完成证据与支持范围见 VALIDATION.md 和 ../README.md。下文保留完整产品设计，M3 项仍为后续目标。

## 1. 产品目标

构建一款以真实 MIPS 执行为基础、以程序理解为核心的现代 IDE。让学生在同一工作区编辑、查询、运行、追踪和解释汇编程序；让教师通过实际机器状态讲解程序，减少 PDF、代码、寄存器、内存和控制台之间的注意力切换。

用户包括初学汇编的学生、已具备编程经验的学生和授课教师。产品保留完整编辑与调试能力，帮助用户从局部疑问出发理解整体程序。

核心问题：学生需要同时在脑中维护操作数含义、寄存器值、内存地址与内容、数值表示、调用关系、控制流和下一步变化。IDE 应把这些关系外显，并随执行保持一致。

北极星指标：用户在暂停处能回答“本步读取什么、改变什么、为何走到下一位置”，并能用工具找到证据。教学效果需要实际试用验证，不预先宣称已经达成。

## 2. 完整设计原则

### P01 真实执行是唯一事实来源

复用 MARS 汇编／执行核心作为优先路线，固定上游版本并建立兼容基线。寄存器、内存、地址、伪指令展开、异常和 syscall 的展示必须与该运行配置一致。前端不能另写一套实际执行规则。已有 Task1 HTML 用于交互参考；其自定义解释器不作为新 IDE 的执行核心。

### P02 信息按需展开，专业能力始终可达

使用统一工作区。默认聚焦当前上下文，全部寄存器、实际指令和完整内存始终可以打开。教学布局是字号、过滤和固定对象的组合，不改变机器语义。避免用强制教程阻挡编辑与调试。

### P03 代码中的对象都应可查询

指令、操作数、寄存器、立即数、标签、地址表达式和 syscall 都具有稳定语义身份。悬停速查；Cmd/Ctrl＋点击或 F12 跳转定义／说明；Peek 原地展开；查找引用区分读、写、跳转；对象和表达式可固定观察。

### P04 对象与关系都可导航

寄存器与对应操作数、符号与内存、调用与返回、输出与产生它的步骤建立双向导航。每条关系能点击查看来源。仅仅颜色一致不算完整关联。

### P05 时间、关系类型和对象身份分别编码

线型表示时间：实线为选中步骤的实际执行，虚线为紧随其后的预览。颜色表示读取、写入、控制转移等关系类型。选中或固定对象表示关注范围，不给每个寄存器永久分配独立颜色。

### P06 时间语义必须明确

状态 S_n 表示完成 n 条机器指令后的状态；PC(S_n) 指向下一条待执行指令。事件 E_n 是 S_(n-1) → S_n 的实际变化。暂停在 S_n 时，实线呈现 E_n，虚线呈现基于 S_n 的下一步预览 P_(n+1)。界面使用“刚完成 #n”和“即将执行 #n+1”，避免“当前行”歧义。

S_0 无已完成事件，只显示预览。历史选择 n 时，所有面板共同显示 S_n 与 E_n，并标记历史模式。程序结束时无下一步。写入相同值也应记录为写入；异常步骤记录实际提交效果与异常，不能凭空补齐未完成效果。

### P07 预览不产生副作用

预览具有独立状态：确定、部分已知、等待输入、外部结果未知、不支持。不得为画箭头提前消费输入、修改文件、输出内容或改变真实机器。优先使用核心提供的执行语义与隔离快照；不能安全预览时保留已知关系并明确未知结果。

### P08 事实、约定和意图区分呈现

分别标注 ISA 行为、汇编器展开、MARS 服务约定、调用约定、静态分析推断、课程注释。“sw 写入四字节”是执行事实；“为了保存返回地址”可能是约定或注释。寄存器并无运行时指针类型，地址预览需按使用上下文解释。

### P09 数值表示与数据身份分离

同一数据可同时显示十六进制、十进制、有／无符号、二进制和 ASCII。字符仅在合适范围显示；字符串编码与终止条件明确。立即数扩展、访问宽度、对齐、字节序在相关操作处可查。

### P10 局部操作与程序整体相互联动

源码、展开指令、控制流图、实际轨迹共享位置映射。明确“可能路径”和“本次已走路径”。间接跳转目标无法静态确定时保持未知；循环和函数识别具有置信来源，不能把所有标签视作函数。

### P11 密度可控，位置稳定

默认显示选中步骤及下一步相关对象。关联线可独立过滤、固定、淡化。执行不会任意重排观察项；输入、滚动和编辑不被线条拦截。滚动出视野的目标使用边缘锚点，不强制把所有窗口滚到目标。

### P12 调试可逆性具有明确边界

寄存器、内存、PC、调用跟踪、输入游标、控制台和虚拟文件状态共同形成可回放会话。外部真实副作用不声称可以撤销。首版以会话虚拟文件系统支持确定性输入输出；主机文件通过显式导入／导出交互处理。

### P13 课程是可移植配置

普通工程无需课件即可使用。课程包可额外提供讲解锚点、输入、断点、观察项、布局和预测题。源码编辑后锚点失效应提示，不静默指向无关行。教师注释与源码及机器事实分别保存。

### P14 可访问性与运行效率属于核心质量

支持键盘、命令面板、可发现快捷键、缩放、明暗主题和减少动画；不单靠颜色传意。运行时批量更新视图，暂停时展示精确信息。历史分段、检查点和容量上限可见，不能无界保留整份内存快照。

### P15 维护边界清楚

核心适配、调试会话、语义模型、可视化和课程配置分层。以职责清晰的接口和对象封装实现，避免通用巨型管理器与过深继承。上游修改保持小且可追踪；派生视图可由事件重建；解释模板可测试、可本地化。

## 3. 工作区与交互设计

默认布局：左侧工程与大纲，中央编辑器，右侧上下文检查器，底部控制台／历史／内存／问题列表。面板可移动、折叠、固定，布局可保存。

### 3.1 编辑与查询

支持多文件、分栏、工程搜索、汇编诊断、指令和符号补全、定义跳转、引用、行内说明。寄存器速查包含当前快照值、最后写入及调用约定。地址表达式显示基址＋偏移＝有效地址及目标内容。未运行代码上的当前快照不得冒充未来执行值。

伪指令可展开实际指令与地址。源码步进是多个机器事件的可展开分组；机器步进始终逐条执行。断点、异常和输入等待可中断源码分组，分组不得隐藏中间读写或 delay slot。

### 3.2 叠加层视觉规范

| 属性 | 含义 |
| --- | --- |
| 实线 | 选中步骤的真实事件 |
| 虚线 | 下一步预览，与实线独立开关 |
| 蓝色单箭头 | 数据来源 → 读取／运算位置 |
| 橙色单箭头 | 运算结果 → 写入目标 |
| 紫色单箭头 | 实际或预览的控制转移 |
| 无箭头细线 | 对象对应关系；静态对应关系另有独立开关与图例 |
| 双箭头 | 仅用于确有双向含义的关系，不合并读后写 |
| 短标签 | 步骤编号、访问宽度、值、条件或地址 |

线条半透明，选中关系提高对比度。读写同一寄存器使用两个方向和 before／after 值。多操作数集中到指令附近运算节点，再连接目标；关系默认按需显示，提供本步全部关系模式。长路径沿面板空隙布线，离屏端点变成可点击锚点。线条不得遮挡文字或吞掉编辑器输入。

所有锚点由语义对象 ID 定位，结合编辑器实际布局计算坐标；缩放、滚动、分栏、虚拟化和文件切换后更新。不可依赖源码文本模糊匹配或固定屏幕坐标。

例：lbu $t0,0($s0) 的实线连接基址、有效地址、字节和目标寄存器；随后 beqz 的虚线使用加载后的值预览分支。展示关系不暗示处理器内部时钟阶段；动画仅为软件执行解释。

### 3.3 调试与历史

运行、暂停、机器／源码步进、跨过／跳出调用、回退、运行到光标、条件断点、读写观察点。暂停前断点时显示上一实际事件和将执行指令，明确断点尚未执行。历史中可定位写入、输出、调用和异常。

修改代码使已有汇编映像和源码映射过期；要求重新汇编，旧轨迹继续关联旧源码版本。修改寄存器或内存产生显式编辑事件，废弃后续预览并建立新的轨迹分支，避免混用历史。

### 3.4 syscall 与文件

按当前 $v0 展示服务、参数及语义角色；执行后展示返回值、内存范围和文件游标变化。控制台输出可回链执行步骤。输入等待保留清晰状态。首先支持两个示例所需服务，其他服务的可预览／可回退能力明确列出。

### 3.5 结构与路径

控制流图展示基本块、条件边和循环区域；轨迹叠加已走边及次数。循环体进入次数与回跳次数分别标注。支持折叠调用和重复迭代，展开任意一次查看实际值。非标准调用约定时，调用栈标注跟踪依据及不完整状态。

### 3.6 来源追踪

第一阶段支持“最后谁写入此值”、全部静态引用及本次动态读写。后续通过数据依赖扩展到跨步骤来源链。必须区分“最后写入记录”和完整数据依赖分析。

## 4. 技术架构方向

建议路线：现代 Web UI＋本地 Java 执行服务＋固定版本 MARS 核心。首先验证无界面运行、步进控制、状态采集与源码映射；桌面壳和具体编辑器库在验证后选择。纯浏览器运行是后续目标。

模块职责：

1. CoreAdapter：汇编、执行、暂停、机器状态、异常和核心能力表。
2. DebugSession：会话状态机、版本、输入输出、断点、历史及预览生命周期。
3. ProgramModel：工程文件、符号、源码映射、展开指令与控制流。
4. TraceStore：执行事件、检查点、变化索引、回放与容量策略。
5. SemanticInspector：指令知识、操作数角色、服务说明、值与地址表示。
6. OverlayRenderer：语义关系到界面锚点及连线；只消费模型，不决定机器行为。
7. LessonPackage：教学配置、注释、布局、示例与可移植资源。

执行服务与界面使用版本化协议。每个请求／事件携带 sessionId、programVersion、stateVersion，丢弃过期预览。运行、等待输入、暂停、结束、异常是显式会话状态。

最小事件记录：stepId、PC before/after、源码位置与展开索引、寄存器读取／写入、内存访问地址／宽度／字节 before/after、分支判断及实际去向、syscall 与 I/O 变化、异常、运行配置及 pending branch 信息。

仅靠状态 diff 不能恢复所有读取和写入：写入相同值无 diff，访存观察器也可能混入 UI 读取。M0 必须验证带执行来源标记的事件采集，或明确需要增加的核心钩子。预览应复用核心语义，无法复用时先降低覆盖范围，避免维护第二个不一致的解释器。

delay slot、伪指令设置、内存配置和输入编码作为项目运行配置保留。兼容性是相对于固定核心及明确配置进行验证。

## 5. Goal G1：建立可用于真实课堂的现代 MIPS IDE

目标陈述：交付可离线启动、支持真实多文件 MIPS 工程的桌面 IDE，在同一工作区完成编辑、查询、执行、回退及关系叠加，让 hexOut 与 Task1 两种代表程序能够完整教学和独立调试，并能载入未专门适配的同类程序。

优先级：执行与时间正确性 → 完整交互闭环 → 视觉清晰 → 功能广度。

### M0：执行核心可行性与协议基线

工作：固定上游 commit／许可；复现构建；梳理执行与 GUI 耦合；验证无界面汇编、单步、寄存器／内存读写采集、伪指令映射、输入等待、回退及延迟分支；完成最小服务原型与能力矩阵。

交付：可复现启动命令、核心适配原型、样例执行事件、兼容性报告和架构决定记录。

验收：hexOut 与 Task1 可从无界面接口运行；关键步骤的 PC、写入和输出与原 MARS 在相同配置下相符；证明能够捕获读取及同值写入；明确副作用和预览的支持边界。失败项形成具体调整方案，不能用假数据界面替代。

### M1：首个可教学的完整纵向版本

工作：多文件编辑与汇编诊断；基本查询与定义跳转；控制台；寄存器／内存；机器步进与基本回退；本步实线／下一步虚线；地址定位；服务参数检查。

验收：实际执行 hexOut 和 Task1；lbu→beqz、sw／lw、移位→ASCII 输出、jal／jr 均能查看关联；两类线独立开关；输入 syscall 预览不消费输入；缩放与滚动后端点准确；不依赖程序文件名或固定地址。

M1 是首个课堂试用版本，而非仅有外观的原型。

### M2：现代 IDE 与结构化理解

工作：源码步进与展开、引用分类、条件断点与观察点、执行到下次写入、控制流图、循环与调用轨迹、历史定位和基础来源追踪。

验收：伪指令中间断点与异常可见；延迟分支配置下路径正确；循环次数定义清楚；跨文件导航和调用返回联动；载入第三个未适配程序验证通用性。

### M3：课堂复用与发布质量

工作：课程包、固定讲解布局、离线打包、会话导入导出、文档、性能和可访问性验证。先验证 macOS，再验证 Windows；发布支持范围以实测为准。

验收：在干净环境启动；导入工程后无需手动摆放地址关系；课程包迁移后断点和注释可定位；完成一次真实课堂试用并记录理解困难与误操作；性能满足下述测试目标。

### 后续扩展

完整跨步数据依赖、更多 syscall 回放、复杂条件表达式、Web 运行时、可选 AI 解释。AI 解释不得进入确定性执行与基础说明链路。首版不加入 C 编译器、流水线／缓存仿真、账户系统或多人云协作。

## 6. 验收矩阵与性能目标

| 场景 | 必须验证的内容 |
| --- | --- |
| hexOut 输入 898 | 输出 00000382；移位、数值表示和 ASCII 转换可追踪 |
| Task1 正常／空文件／找不到文件 | 输出、错误分支、返回值及恢复的栈一致 |
| Task1 容量边界与含 NUL 输入 | 区分实际读取内容和程序实际打印行为 |
| sw 后 lw、同值写入、零寄存器 | 访问宽度、方向和真实提交语义正确 |
| 伪指令与 delay slot | 源码映射、PC、返回地址和控制流一致 |
| 非法访存或对齐异常 | 停止位置与已提交状态准确 |
| 输入等待与回退 | 不重复消费输入；回放结果可重复 |
| 编辑后重汇编及历史查看 | 旧轨迹不绑定新源码；过期预览不会覆盖新状态 |
| 窗口缩放、分栏、离屏对象 | 连线锚点正确、编辑可操作 |

测试策略：核心与原 MARS 做代表性差分；事件协议做不变量检查；界面测实际操作链；人工检查连线可读性。重点验证语义与用户任务，不堆砌与实现同构的测试。

初始性能预算（待 M0 固定测试机器与工程规模后实测）：暂停状态的查询／高亮 p95 < 100 ms，普通单步到可见状态 p95 < 150 ms；运行时界面更新节流；十万步会话具有明确内存上限与历史截断提示。性能数据必须附测试条件，不能把设计预算报告为已达标。

教学试用任务：找到地址表达式对应内存；解释 50／0x32／'2'；预测分支；找到寄存器最后写入；说明 jal 后如何返回。记录完成时间、求助次数和错误类型；与现有工具比较后再调整呈现。

## 7. 执行约定与当前状态

按 M0→M1→M2→M3 推进。每阶段汇报可运行成果、验证证据、已知缺口和下一步。后续实现可以自主处理可逆的工程选择；架构变化更新决定记录，阶段完成依据验收项而非已写代码量。

当前已完成：产品定位、核心源码验证、GitHub fork、执行接口、现代编辑器与调试视图、叠加层、M2 结构化调试及本地验收。项目的具体支持边界与后续 M3 项见 README 和 VALIDATION。

下一阶段为 M3：课堂试用反馈、课程包、安装包、长会话性能和跨平台验证。
