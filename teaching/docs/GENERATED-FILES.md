# 文本文件与程序写文件

`.txt` 等文本文件直接在中央编辑区和标签页打开，支持编辑、保存、重命名、删除和工程 ZIP／JSON 导出。没有“输入编辑器”或“输出预览窗口”。源码以外的文本不会参与汇编语法检查；汇编仍使用最近打开的源码或工程入口。

程序通过 syscall 13／15 写出的文本同步为同一路径的普通工程文件。程序覆盖同名文件时，工程内容随实际写入更新；生成后可像其他文本一样修改和保存。状态刷新只同步运行中发生变化的字节，不会用旧结果反复覆盖用户编辑。编辑工程文件不会改写调试器已记录的执行快照；下次汇编会读取保存的文本。

生成文件与普通文本一样保存在浏览器工程和导出包中，重新汇编不会从工程删除这些文件。源码文件不会被运行生成的数据替换。

后端 `state.generatedFiles` 是路径到 `{base64,size,hash}` 的映射；前端以它识别实际运行写入。前端在每个命令里带上 `generatedKnown`（路径到已持有的 hash），内容未变的文件只回 `size` 和 `hash`，`base64` 为 `null`，避免单步和逐步运行时反复传整份文件（2026-11-04）。网关需原样转发 `generatedKnown`。界面不按输入／输出分组，不再给输出文本设置只读限制。

验证：`text_editor_browser.py <地址>` 检查编辑、刷新恢复、导出、生成新文本与 syscall 使用修改内容；`output_browser.py <地址>` 检查生成文本的编辑保存、导出以及状态刷新不会覆盖编辑。

编辑文本文件不会让已暂停的程序失效：调试继续使用汇编时的内容，横幅提示重新汇编后才使用新内容（2026-11-04）。源码文件的修改仍要求重新汇编。
