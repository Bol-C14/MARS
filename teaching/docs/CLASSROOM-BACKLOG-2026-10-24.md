## P1 · 网页版“打开本地文件夹”模式（2026-10-30 新增）

**状态：未实现。用户当前只要求记录与推送，后续交给 Claude 实现；本轮不改代码或上线。**

### 目标与边界

学生在现有网页中主动选择并授权一个本地课程文件夹，文件树直接对应该目录，在 IDE 内编辑后保存回原文件，减少反复导入/导出。不制作桌面安装包，不接入 LLM，不改变 MARS 的执行语义或当前汇编范围设计。

**直接打开/访问与导入使用必须是两种明确的工作方式，不能共用一个含糊的“打开文件夹”入口，也不能仅更换现有导入按钮的文字。** 现有通过文件夹选择器读取内容的功能仍是导入副本，不具备持续写回原文件的能力。

### 两种模式的 UI 与入口

| 维度 | 本地文件夹模式：直接打开/访问 | 浏览器工程模式：导入副本 |
| --- | --- | --- |
| 入口建议 | **打开本地文件夹…**，说明“授权访问，保存会写回原文件” | **导入到浏览器工程…**，区分“替换当前工程”和“追加文件” |
| 数据来源 | 授权目录里的实际文件，与磁盘保持明确关联 | 读取一份文件/文件夹/ZIP/JSON 的内容副本 |
| 保存 | Cmd/Ctrl+S 或保存按钮写回实际文件；未获写权限不能声称已保存到磁盘 | 自动保存/手动保存到当前浏览器；不写回导入来源 |
| 新建、重命名、移动、删除 | 会影响实际磁盘，需要在动作及结果中明确说明 | 只影响浏览器工程副本，来源磁盘不变 |
| 导出 | 可另存副本或导出工程；不替代正常写回 | 下载文件或 ZIP/JSON，供交作业或跨设备使用 |
| 常驻状态 | “本地文件夹 · 课程目录名”、未保存状态、真实写入结果及授权状态 | “浏览器工程”、已存浏览器/未能保存等状态 |

表中的入口名称是可用文案方向，具体菜单排布可结合现有工程菜单设计；两种行为、保存目标和影响范围的区别是必须满足的要求。

### 动态详情示例

对于 `add $s0, $s0, $t0`，简短浮窗可给出本行公式，**详细检查器**依次展示：

1. 通用规则：`$a = $b + $c`，或等价、明确的目标/来源占位符。
2. 本行代入：`$s0 = $s0 + $t0`。
3. 本次执行前的数值：例如 `$s0 = 7`、`$t0 = 3`，因此 `7 + 3 = 10`。
4. 实际结果：`$s0：7 → 10`；注明这是刚执行的结果，还是尚未执行的预览。
