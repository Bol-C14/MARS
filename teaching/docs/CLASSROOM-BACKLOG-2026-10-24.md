## P0 · 默认当前文件与显式联合汇编

### 课堂现象

学生将课程文件夹导入，文件树中同时有 `hello.s` 和 `hexOut.s`。两者是独立练习，都定义 `.globl main` / `main:`。学生查看 `hexOut.s` 并点“汇编”，出现：

```text
"main" already defined as global in a different file.
```

当时入口仍标在 `hello.s`，但仅改入口也不能解决问题，因为所有源码仍被送入汇编器。

### 待办

- [ ] 默认模式只汇编当前正在编辑的 `.s` / `.asm`；其他练习仍保留在文件树中，不参与符号合并。
- [ ] 单独提供明确的“多文件联合汇编”模式，显式选择参与的源码和其中的入口文件。
- [ ] 清楚展示当前模式、参与文件与执行目标，避免把“打开的标签”“入口文件”“联合汇编文件集合”混为一谈。
- [ ] 用户切换到另一独立练习后，不能静默运行先前文件的程序；明确处理需要重新汇编的状态。区分用户切换文件与调试器自动跟随跨文件执行。
- [ ] 模式或参与文件改变时，避免继续使用旧地址、断点映射或轨迹；不删除任何学生源码。
- [ ] ZIP/JSON 工程保存联合汇编选择；兼容既有工程，旧工程缺少新字段时使用安全、清晰的默认行为。
- [ ] 内置 `Task 1` 等确实依赖多个源码的示例明确声明其联合汇编配置。

### 验收

- [ ] 同时导入两个各自含 `main` 的练习，默认分别打开、汇编和运行均成功；另一个文件始终留在树中。
- [ ] `main.s` + helper 源码经显式选择后可联合汇编；未选的另一个独立练习不干扰。
- [ ] 非 `main.s` 文件名、嵌套目录、切换模式、保存/重开工程均保持正确的汇编范围。
- [ ] 确实选入两个冲突入口时，诊断能说明涉及的文件与联合汇编选择。

## P1 · 更直观的动态指令浮窗

### 学生需要看到的层次

对于 `add $s0, $s0, $t0`，在现有浮窗中额外展示：

1. 通用规则：`$a = $b + $c`，或等价、明确的目标/来源占位符。
2. 本行代入：`$s0 = $s0 + $t0`。
3. 本次执行前的数值：例如 `$s0 = 7`、`$t0 = 3`，因此 `7 + 3 = 10`。
4. 实际结果：`$s0：7 → 10`；注明这是刚执行的结果，还是尚未执行的预览。

### 待办与验收

- [ ] 公式、寄存器名称、数值和结果均按当前源码与执行情景生成，不固定写死示例。
- [ ] 目标与来源相同（如 `$s0`）时，来源使用写入前数值，不能用执行后的值再次计算。
- [ ] 未汇编、代码已修改、没有有效执行状态时，只显示可确定的规则，不编造当前值或结果。
- [ ] 回退、历史回放、循环中同一行多次执行时，说明与所选执行步一致。
- [ ] `$zero` 写入丢弃、溢出/异常、条件写入未发生、HI/LO 结果等保留真实机器语义。
- [ ] 优先复用现有操作数解析、访问记录与 `beats.js`，不要另造一套执行器。

## P1 · syscall 分服务教学说明

### 课堂现象

学生对 syscall 的不同用途缺少概念，难以区分“打印整数”“打印字符”“读取整数”，也不清楚 `$v0` 在调用前是服务号、调用后可能变成返回值。

### 待办与验收

- [ ] 按服务展示“做什么 → 需要哪些参数 → 发生什么 → 哪些寄存器/终端发生变化”。
- [ ] 先覆盖课堂常用服务：1 打印整数、4 打印字符串、5 读取整数、8 读取字符串、10 退出、11 打印字符、12 读取字符；其他服务按实际支持范围扩展。
- [ ] 字符输出解释字符编码，例如 `$v0=11, $a0=45` 输出 `-`；整数输出服务 1 使用相同参数值会输出 `45`。
- [ ] 对字符串区分地址和内容，不把 `$a0` 的地址值当作要显示的整数或字符串本身。
- [ ] 读取输入明确显示等待状态、输入位置和完成后的返回值；输入尚未发生时不显示虚构结果。
- [ ] 保存调用前的服务号，不能误用读取后已被覆盖的 `$v0` 来解释刚才调用了哪个服务。
- [ ] 不支持的 syscall 明确说明边界；与现有虚拟文件和可回放语义一致。

## P1 · 二进制模式寄存器值完整展示

- [ ] 解决右侧寄存器在 BIN 模式下过长、被裁剪或溢出的情况。

- [ ] 保留位的顺序、前导零与真实位宽；负数的补码位模式不被错误改写成“负号加绝对值”。
- [ ] 复制数值、寄存器名、变化高亮和其他显示模式仍正常。
- [ ] 覆盖 0、-1、正负边界值，以及窄侧栏与正常桌面窗口；只改变显示，不改执行状态。

## P1 · syscall 的终端注意提示

- [ ] 打印整数、字符、字符串等产生输出时，让终端区域短暂闪亮或有明确的轻量提示。
- [ ] 读取输入进入等待时，突出输入区域，让学生知道要在终端输入；输入完成后的反馈也要清楚。
- [ ] 由真实执行事件触发；静态悬停、未执行预览和仅刷新状态不应伪装成刚发生了 I/O。
- [ ] 快速连续执行不叠加大量闪烁；减少动态效果设置下改为静态提示。
- [ ] 不抢走正在编辑代码的键盘焦点，不改变程序输出或输入消费顺序。

## P2 · 专注模式中的未走分支

- [ ] 除当前将走/已走的路径外，展示条件分支的另一条未走路径或代码片段。
- [ ] 同时展示本次比较值和条件结果，明确区分“实际执行”“预测下一步”“未走路径”。
- [ ] 未走路径应能看清目标标签及相关源码；折叠/展开方式需避免让专注视图失去重点。

## P2 · 寄存器逐位运算动画

### 目标与建议拆分

学生对寄存器内部处理不熟悉。希望在专注模式中可主动展开每一位的变化，而不是只看最终十进制结果。以下是实现拆分建议，不是已经做出的界面决定。

- [ ] 第一阶段：`sll` / `srl` / `sra`，展示源值、移位数量、移出位、补入的 0 或符号位、最终结果；区分逻辑右移与算术右移。
- [ ] 第二阶段：加减与按位运算，展示对齐的源寄存器、目标寄存器、进位/借位与结果；正确区分补码、溢出和异常。
- [ ] 后续：乘除，展示参与的位宽和有符号/无符号语义；乘法的 HI/LO 与除法的商/余数不能混淆。
- [ ] 每段动画可暂停、逐步查看和重放，减少动态效果时提供等价静态分解。
- [ ] 动画来自所选真实执行步；回退和循环时随状态更新，不额外执行指令或改变输入。
- [ ] 在整条伪指令的解释与机器指令内部步骤之间明确区分，避免再次让学生误以为源码的一行必须操作两次。
- [ ] 提供小而有代表性的课堂验证用例：移位补位、连续进位、负数、0、边界值。
